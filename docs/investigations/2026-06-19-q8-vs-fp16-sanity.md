# Q8_0 vs FP16 token-level sanity (Qwen3-8B)

**Date:** 2026-06-19
**Branch:** `feat/phase1-mvp`
**Question:** is `--quantize-decode` (Q8_0 single-stream path) safe to
recommend in production, and what is the *actual* shape of the precision
tradeoff?

## TL;DR

Q8 is safe to ship as an opt-in flag for throughput-sensitive workloads
where token-level reproducibility is not contractual. On an 8-prompt
Qwen3-8B greedy 256-token check: **3/8 character-identical, 5/8
mid-reply divergence (average at 44% into the reply), 8/8 semantically
equivalent**. The diverged completions paraphrase the FP16 answer; they
do not contradict it. Q8 should not be the default until broader sanity
coverage exists (multi-family, NLL drift on standardised slices, failure
catalogue) — see `docs/RUNBOOK.md` "Why is `--quantize-decode` not the
default?".

## Method

Same prompts hit forge twice on Qwen3-8B (BF16 → F16 cast at load):

1. Default startup (`./target/release/forge-server ...`) → collect 8
   greedy 256-token completions.
2. Restart with `--quantize-decode` → collect the same 8 completions.

Compare character-by-character on the concatenated thinking + visible
text (Qwen3 outputs `<think>...</think>` wrappers, stripped before
comparison).

Reproducible via `scripts/q8_sanity.py` (committed alongside this
report).

## Interpretation

### Where the divergence comes from

Q8_0 stores 32 weights per block as INT8 + a shared FP16 scale, giving
**effective ~8 mantissa bits** per weight versus FP16's 10. This ~2-bit
loss is enough to perturb a softmax probability vector when the top-2
candidates are close to a tie. Greedy decode picks top-1 deterministically,
so any flip past the tie threshold compounds: the next step's KV context
includes the flipped token, the trajectory diverges, and the rest of the
reply rewrites itself in token space — but stays in the same semantic
neighbourhood, because the model still knows what the user asked.

This is the same mechanism that produces inter-engine divergence in the
existing BF16-vs-F16 sanity check (memory `forge-fa2-paged-decode`,
2026-06-15): forge cast-to-F16 vs pegainfer native BF16 also got 5/8
identical / 3/8 mid-reply divergence on the same prompts. Q8 sits one
notch noisier than that (3/8 identical), which is expected from a
nominally larger precision delta.

### Where divergence shows up in the reply

All five divergences happen mid-reply (8% to 99%), not at the opening.
The first ~100 characters of every reply are character-identical, which
matches the precision-flip explanation: until the model encounters a
genuinely close softmax decision, both paths produce the same token.
Long replies have more chances to hit a close decision, which is why
prompt 4 (1310 chars) diverges only at 99% but prompts 1 and 8 (also
long) diverge earlier — depends on the specific topology of the
decision boundary along each trajectory.

### What does *not* show up

- No empty replies, no truncation, no `<|endoftext|>` flips. Both runs
  produced the full 256 tokens requested.
- No semantic contradiction. Every Q8 reply gives the same answer as
  the corresponding FP16 reply; only the wording differs after the
  divergence point.
- No prompt-specific quality cliff. Divergence is roughly evenly
  distributed across prompt types (translation, math, summarisation,
  factual recall, code).

## Verdict

**Ship as opt-in.** RUNBOOK ("When to use `--quantize-decode`")
documents the recommended-for / avoid-when matrix using this sanity
data as evidence. The flag is on the table for users to flip; we just
don't promise it produces byte-identical text.

**Do not default-on yet.** RUNBOOK ("Why is `--quantize-decode` not the
default?") lists what we'd want before flipping:

1. **Multi-family sanity.** At minimum Qwen2.5, Qwen3, Llama-3 ×
   {~1B, ~8B}. Eight prompts on one model is a spot check, not
   coverage.
2. **Quantitative quality signal.** NLL or perplexity drift versus
   FP16 on a standard slice (WikiText, C4) — not just identity-rate
   on hand-picked prompts. The 3/8 identity number from this report
   is too coarse to defend a default flip.
3. **Failure-mode catalogue.** Surface the kinds of prompts that
   trigger larger Q8 divergence (e.g., very long replies, prompts that
   exercise rare tokens, math chains) so operators can pin
   `--quantize-decode false` for those workloads.
